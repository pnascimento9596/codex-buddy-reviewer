# v0.5.0-rc.2 release note

## Decision

Publish the reviewer-adapter reconciliation as a second release candidate through the protected public-source workflow. The rc.2 source preserves the post-rc.1 public process, cancellation, temporary-state, OpenCode plugin-isolation, and POSIX Grok FIFO behavior while adding the private hardening line's no-loss response, transport, deadline, and result-acceptance contracts.

## Reconciliation summary

The no-loss family removes the five-finding input ceiling across the checked-in schema, runtime validation, prompts, aggregation inputs, and outbox inputs while retaining the complete attributed source result behind the bounded five-item presentation. Malformed or transport-invalid responses are preserved once in private mode-`0600` evidence with safe failure metadata, raw transport bytes are stripped from the propagating error after preservation, OpenCode high-reasoning events are tolerated without becoming review text, and Grok's observed `end_turn` envelope is accepted under the closed transport parser.

The public post-rc.1 family remains authoritative for approved provider-request dispatch, provider process containment and lifecycle, temporary-state cleanup, cancellation signaling, OpenCode environment isolation without `OPENCODE_DISABLE_DEFAULT_PLUGINS`, and the POSIX FIFO prompt bridge used by direct Grok. The composed result raises the reasoning-review deadline to 1800 seconds, bounds each stall re-arm to a 30-second completion grace, and accepts an authenticated completed result even when a stale deadline flag was set.

## Public provenance contract

The rc.2 artifact contains Byte, Mochi, Orbit, Bella, and Lupo. Each package carries a machine-readable public Apache-2.0 grant in `assets/pets/<pet-id>/provenance.json`; Bella and Lupo specifically record project-owner source-asset attestations dated 2026-07-19 in `assets/pets/buddy-bella/provenance.json` and `assets/pets/buddy-lupo/provenance.json`. Those operative records and the already-published rc.1 artifact establish the five-pet contract; the older private-only statements in the read-only private validation document are stale and require a one-line correction in the next authorized private-repository lane.

## RC promotion gate

- [ ] The frozen exact source head passes the complete Node 24 local suite three consecutive times, plugin/skill and public-boundary validation, the hardened consumer proof, adversarial parent-line accounting, and final GLM 5.2 plus Grok 4.5 reviews.
- [ ] Protected GitHub Actions passes the repository credential scan and the complete Ubuntu, macOS, Windows x64, Node 22, and Node 24 matrix at the exact PR and merged source head; the Windows job is observed at terminal success by run and job ID.
- [ ] The generated positive artifact is byte-verified against the trusted source policy, archived deterministically, re-extracted, and verified again with the exact source commit and version.
- [ ] The final version/cachebuster source is merged to protected `main`, and the manual release workflow is dispatched from that unchanged head with `version: 0.5.0-rc.2` and `publish: true`.
- [ ] The workflow constructs and publishes only the reconciled parentless artifact commit and annotated `v0.5.0-rc.2` tag, then reconciles the remote tag object, peeled artifact commit, GitHub Release, asset bytes, and provenance attestations.
- [ ] The Codex marketplace ref is moved only after the remote tag is verified, the managed cache is refreshed to rc.2, and the managed-cache consumer proof returns all three fields strictly `true`.

Artifact-bound host-evidence reports are deliberately **not** an rc.2 publication gate. The workflow requires the host-evidence bundle only when publishing stable `v0.5.0`; the five named human pet observations remain a stable-release gate exactly as documented for rc.1.

## Deliberate limitations

- RC publication does not claim stable host acceptance, live Windows provider egress, or completion of the five named pet observations.
- Windows provider use remains fail closed until the separately documented current-user-only state and temporary-root controls have real platform evidence.
- The consumer-proof harness validates the three known no-loss/transport defects; it supplements rather than replaces the complete suite, cross-platform CI, artifact verification, and independent reviews.
