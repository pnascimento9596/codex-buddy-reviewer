# v0.5.0-rc.4 release note

## Decision

Publish the post-rc.3 native-host fixes as a fourth release candidate, exclusively through the protected public-source workflow. The candidate is not stable. It carries the #36 speculative-worker repairs, the #38 host-compatible pet packages, and the #37 first-enable baseline message, and it does not claim a completed artifact-bound five-pet host-e2e bundle until that bundle is collected against the published rc.4 artifact.

## Root causes and fixes

### #36 — speculative pre-review worker (PRs #44, #46)

Two independent defects blocked real-host speculative adoption on rc.3:

1. **Snapshot churn terminalized the worker (PR #44 → `3ac754b`).** `captureTurnSnapshot` throws `turn snapshot changed during capture; retry` when inventory/HEAD changes mid-capture. That throw escaped `stableCheckpoint` into the outer worker `catch` and became terminal `worker_state: failed` instead of returning to debounce.
2. **Detached event-loop drain (PR #46 → `866e359`).** The worker used `fs.watch({ persistent: false })` and unref'd timers. After stdin closed, idle waits left no referenced handles; Node exited under the top-level await (`unsettled top-level await`), leaving `worker_state` active with **no process** and `speculative_launches: 0`.

Post-fix real-host evidence observed exact ready==completed identity `5a646cf0…` with two live speculative launches, outbox order `turn_started` → `review_started` ×2 → `turn_finished` → `review_completed`, and **no** `review_started` after `turn_finished`.

### #38 — pet packages vs Codex 0.146 (PR #45 → `23784a3`)

rc.3 shipped extended 8×11 / 1536×2288 atlases. Codex 0.146.0 accepts the base 8×9 / 1536×1872 host contract used by built-ins and legacy ambient pets. Packaging the extended sheet made Buddy packages undiscoverable in `/pet`. Host-compatible packages restore selectability for Byte, Mochi, Orbit, Bella, and Lupo.

### #37 — first-enable baseline UX (PR #50 → `065c470`)

Enable has no session/turn context, so baseline pre-warm is unsafe. The enable summary and `missing_baseline` Stop message now state that the next turn establishes the private start snapshot at prompt submit and that mid-turn enable does not invent a baseline. Fail-closed no-provider behavior is preserved.
