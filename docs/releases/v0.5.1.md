# v0.5.1 release note

## Decision

Publish the security-fix `v0.5.1` from the exact protected `main` promotion head
after version prep, host-evidence bind, and the bounded fix-delta seal. This
note is not dispatch authorization by itself; dispatch follows the two-phase
protocol in `docs/releases/dispatch-attribution.md` under the owner's standing
2026-08-07 instruction.

## Why this release exists

A platform-independent receipt-replay validation bypass (H07) was reproduced
against the **published v0.5.0 artifact** (tarball sha256
`0b474c51…`, source commit `d23890e`): a forged legacy completion/receipt pair
with a matching digest replays and presents a forged finding title. Every
replay path now enforces the context-free structural receipt contract before
presenting a continuation.

## What lands relative to published v0.5.0

| Item | Content |
|---|---|
| H07 fix | `validateAutomaticReceiptReplay` structural validation on the replay branch; forged legacy pairs rejected, completion marked `invalid_pre_review_receipt` |
| Windows gate | `WINDOWS_PROVIDER_EGRESS_GATE_LIFTED = false` — 0.5.1 never ships a lifted gate while H01–H06 remediation is pending; v0.5.0 blocked posture restored |
| Tests | forged pair never replayed; valid legacy receipt still replays; production gate fail-closed asserted |

## Operator-facing guidance

Upgrade to 0.5.1. If you suspect private runtime state was modified outside
Buddy, disable automatic review, run `data purge --confirm-purge` (automatic
mode disabled), and re-enable. Windows live egress remains blocked in this
release, matching v0.5.0.
